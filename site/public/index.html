What ships in your repo

FastAPI with hexagonal architecture, in memory by default.

Shared agent guidance

AGENTS.md, seven skills (discovery, specify, plan, implement, integrate, review, ship) and four subagent roles (architect, test_engineer, reviewer, security_auditor).

Optional infrastructure

PostgreSQL (SQLAlchemy async + Alembic), Redis and Kafka or RabbitMQ (FastStream publisher + consumer worker) are opt-in.

Checks built in

make check runs Ruff (PEP 8/257 and Bandit rules), mypy --strict, import-linter, pip-audit on the locked tree and pytest with branch coverage ≥ 90%.

Projects keep improving.

Generated repositories stay linked to the template; copier update brings later improvements.

From discovery to delivery

Every generated project ships the same six-phase process as skills in .agents/skills/. Each phase produces a versioned artifact and ends at a gate.

  1. Discovery$discoveryproblem and metrics approved
  2. Specify$specifyacceptance criteria approved
  3. Plan$planplan approved
  4. Implement$implementmake check green
  5. Review$reviewno blocking findings
  6. Ship$shipCI, merge, optional CD

A well-scoped local fix may start at implement with a regression test.

Run your first service

Install Git and make. Docker is needed only for the optional integrations.

The in-memory API listens on http://127.0.0.1:8000.

Use --agent to select an adapter. Codex is the default.

Then open the directory with your coding agent. It reads AGENTS.md first.

View package on PyPI

With uv

uvx igarape new orders-api
cd orders-api
make dev

With pip

For pip, activate a virtual environment with Python 3.12 or newer.

python -m pip install --upgrade igarape

If your installed version is 0.2.0, install uv separately with python -m pip install uv in the same environment. Then generate the service:

igarape new orders-api

Then enter orders-api and run make dev.

Git and delivery behavior
  • If the initial commit fails, Igarapé keeps the scaffold and shows the Git error.
  • The generated Claude Code settings allow specific Git commands for inspection, staging and commits, with confirmation before pushing.
  • With CD and releases enabled, reruns keep the release version when its tag points to the same commit.
